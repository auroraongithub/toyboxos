sync.exe

Local-first, last write wins per document. A change is saved on the device first, so nothing waits on the network.

assistant.exe

With sync on and a server model, the assistant's loop runs on the server, so a chat finishes even after you close the app. Tools that only the app can run are handed back to it, and anything risky waits for your Allow.

%%{init: {"theme":"base","themeVariables":{"primaryColor":"#ffffff","primaryBorderColor":"#151515","primaryTextColor":"#151515","lineColor":"#3b3b3b","actorBkg":"#ffffff","actorBorder":"#151515","noteBkgColor":"#ecece7","noteBorderColor":"#8d8d88","fontFamily":"Atkinson Hyperlegible, sans-serif","fontSize":"14px"}}}%%
sequenceDiagram
  participant You
  participant App as Chat window
  participant Run as Background run
  participant AI as AI proxy
  participant M as Provider
  You->>App: message
  App->>Run: start the run
  loop up to 16 steps
    Run->>AI: request
    AI->>M: adds the key
    M-->>Run: reply / tool calls
    alt server tool: Moodle, search, web
      Run->>Run: runs it on the server
    else app tool: windows, data, timer
      Run-->>App: pending call
      App->>App: runs it on this device's data
      App-->>Run: result
    else risky: delete, run, merge
      App->>You: Allow card
      You-->>App: Allow or Stop
    end
    Run->>Run: saves each message
  end
  Run-->>App: messages arrive through sync
  Note over App,Run: local models skip the server and loop in the app

deploy.exe

Two ways in, one way out: a new release that installed apps pick up by themselves. Native code (Windows tray, Android alarms) still needs a new installer.

Modular good

One file per window, one shared data layer, a registry. The assistant is split into tools, view and runner; the editor and whiteboard keep their helpers in their own files.

Practices good

Few dependencies, no eval, keys stay on the server, sandboxed previews, approvals for risky actions. Every ignored error says why or logs a warning.

Readable by humans fair to good

Formatted with Prettier and ruff, checked by npm run lint. Screen templates keep their long lines, and core names stay short (D, W, ls).

Maintainable fair

Unit, server and browser tests (npm run test:ui, desktop and phone). No type checking, and the editor and whiteboard components are still about 1,300 lines each.
